# Local remediation and release status

Updated 13 October 2026, India time. This continues the [11 October audit](PRODUCTION_READINESS_AUDIT.md). All source changes are local; no commits, pushes, uploads, or deployment were performed. The original source is backed up at `.local/pre-fixes/source.tgz`. This folder has no Git metadata.

The audited security, microphone, provider, model, packaging, diagnostics, and release-gate defects have source fixes. Public launch still requires configured production infrastructure and evidence from the intended hardware and physical devices. Local checks do not certify production capacity or availability.

## Verified evidence

Current verification results and their limits are recorded in [REMEDIATION_EVIDENCE.json](REMEDIATION_EVIDENCE.json). Detailed local logs, browser scripts and screenshots live under `.local/verification/`; they contain synthetic test data and are not a production monitoring system.

The clean-install gate passes TypeScript, lint, 20 frontend tests, the production build, npm advisory scanning, Python package consistency, 15 Python tests plus four subtests, compilation and pip-audit. Dependency scans reported no known vulnerabilities at the time of execution; this does not establish the absence of undiscovered vulnerabilities or certify the operating-system image.

Real shared-store tests verify private access, same-origin/caller-room denial, global/per-owner capacity, cross-owner cleanup denial and owner release. Separate quota tests verify atomic RPM enforcement, token refunds without refunding requests, cooldown TTL preservation, and rejection of an unavailable shared store. Production diagnostics return 404. A stopped worker's expired heartbeat changed readiness from 200 to 503 in the earlier repair verification.

The earlier strict two-user gate received two correct, spoken answers at 4,100 and 4,962 ms to first client audio. An earlier single-call run narrowly failed at 5,006 ms. The strict five-second gate correctly rejected that run. Neither a tiny pass sample nor one failed timing measurement estimates production p95. Warm local TTS measured worst RTF 0.732 over three samples; cold synthesis took 8,376 ms. Startup and network variability remain material.

The real synthetic interruption gate stopped playback in 607 ms and received a recognized follow-up and spoken Tokyo answer. Metrics exported actual reported input/output token usage and completed turn durations with zero pipeline errors during that successful run. All seven advertised languages produced non-silent 24 kHz output; this proves audio generation, not pronunciation quality.

## Before opening public traffic

1. Provision the intended always-on worker hardware/region, dedicated authenticated Redis REST store, HTTPS frontend ingress, signing secret, private-beta access policy and scoped service credentials. Configure direct-origin restrictions and account billing limits. Start with a conservative admission limit.
2. Validate the exact deployed frontend/worker pair, readiness TTL, worker/provider/store loss, shared capacity/quota exhaustion, cross-session denial and rollback. The control contract is `yuki.control.v1` with server-owned consent/deadline metadata.
3. Test speech, interruption, mute/reconnect, device switching and autoplay on desktop Chrome/Safari and physical iOS/Android. Review pronunciation with representative speakers and accessibility with assistive technology.
4. Run a repeated concurrent workload and a sustained soak at the proposed admission limit. Record startup, first client audio, correctness, failure rate, CPU and memory. Increase capacity only after those measurements pass an agreed budget.
5. Confirm retention/data-processing settings, log access/deletion, alert recipients and an operational owner. Connect readiness/synthetic/error/usage alerts and retain compatible rollback images. Release a restricted beta before public admission.

See [deployment configuration](../deploy/README.md), [operations](OPERATIONS.md), and [local verification commands](../README.md). These account-side and device checks remain explicit launch gates; they cannot be completed by changing local source files alone.
